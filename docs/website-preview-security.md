# Hosted website content previews

Hosted content is untrusted, even when it arrives through an authenticated operator connection. A website may intentionally contain JavaScript, malicious markup, remote resources, redirects, or arbitrary binary files. The preview must not grant that content any of the GUI's renderer or preload capabilities.

## Source preview boundary

`WebsiteContentPreview` presents UTF-8 source in a read-only Monaco editor with syntax highlighting. Binary content uses a hexadecimal and printable ASCII view. HTML, SVG, XML, JavaScript, CSS, and Markdown remain source text in this view. Language selection only chooses a locally packaged tokenizer; it does not execute the document or load referenced resources. Links, editing, rich hover/completion content, and unnecessary editor services are disabled.

The source component does not insert HTML, use an iframe/webview, create content-derived resource URLs, or open links. URLs stay selectable source text. The operator can still copy source or export files deliberately; files opened outside the GUI are beyond this preview boundary.

The renderer additionally caps source display at 64 KiB of input and hex display at 4 KiB, regardless of the supplied payload size. Nonprinting and bidirectional formatting controls are shown as explicit Unicode escapes in source previews. Invalid UTF-8 falls back to hex. A prefix ending inside a multibyte character omits the incomplete character and visibly identifies truncation. Previewing never changes hosted bytes.

Textual content opens in the existing standalone Monaco editor window. The editor accepts only textual MIME types and complete UTF-8 content of at most 1 MiB, with matching byte-count metadata and no truncation. It preserves a UTF-8 BOM and consistent original line endings. Missing bytes, binary content, and partial previews cannot become an editable document that might accidentally overwrite the complete file with its prefix. The main process independently enforces import, export, and editor limits and owns filesystem dialogs and network access.

The main process binds an editor to its original source renderer, backend connection, website ID, exact path, content ID, MIME type, and verified content digest. Saving never redirects to a newly selected connection. Existing content requires native overwrite confirmation, then another identity and digest check before the serialized write. Changes by another editor or operator, MIME changes, source reloads, and reconnections require reopening the document. A successful write is verified from returned bytes before updating the editor's saved revision and refreshing website inventory. New text starts as a blank document at an unused path; creating text over an existing path is rejected in favor of opening that content with Edit.

## Browser preview boundary

The explicit **Preview** action opens any stored content type in the default browser through the same validated HTTP/HTTPS opener used by **Open URL**. Main binds an ephemeral HTTP server to `127.0.0.1` on an operating-system-selected port and opens the selected content's encoded URL path. The preview never visits a hosted listener URL, creates an Electron content window, or grants hosted content application preload or IPC access. The browser decides whether a content type is displayed or downloaded.

The server exposes only the selected website's exact stored paths. Relative and absolute same-origin URLs resolve to other stored files from that website. Every GET and HEAD performs a new authenticated backend request, verifies website identity, content size, and any supplied SHA-256, and clears the response's bytes after transmission. Missing resources return 404. Content replacements and MIME changes are visible on the next request to the same preview URL, without reopening the preview. Responses use `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`, `Pragma: no-cache`, and an expired timestamp. There are no ETags, last-modified validators, partial range responses, or application content caches.

The browser receives original content bytes with the stored MIME type, `nosniff`, `no-referrer`, and an HTTP Content Security Policy. Same-origin scripts, inline scripts, CSS, images, fonts, media, and fetches can run so the stored website behaves as a website. Network subresources and connections to other origins, frames, embedded objects, workers, and form submission are blocked. The response applies browser sandbox restrictions, permits scripts and the preview origin, denies framing, and disables sensitive browser permissions. The application renderer's CSP and navigation restrictions remain unchanged. Browser navigation and local browser behavior remain outside Electron's control; this is an active browser preview, not a sanitized static document.

Workers are disabled by CSP, and worker/service-worker script requests are independently denied by the HTTP server. This prevents hosted service workers from registering and intercepting later preview requests with stale cached responses. The server validates the exact loopback Host header and any Origin or Fetch Metadata headers, rejects cross-origin requests, and sends no CORS permission. It accepts only GET and HEAD. Raw request targets are checked before URL normalization; traversal, encoded separators, backslashes, malformed percent escapes, fragments, and control characters are rejected. MIME values are validated before becoming response headers. No request can select a local filesystem path or another website.

Each owner has at most one active preview server, with four servers allowed across the application. The small **Local preview** toolbar button opens a dialog identifying the running website and its loopback URL independently of the website selected for editing. Closing this dialog leaves the server running. The **Preview website** dropdown shows the currently hosted website; selecting another entry starts its preview and revokes the previous origin. It includes the full website catalog regardless of the sidebar filter and does not change the website selected for editing. Selecting a website in the sidebar leaves the running preview unchanged. Inside the dialog, **Open in browser** reopens the active preview and **Stop server** closes its listener and active connections. When stopped, the dropdown shows **Choose a website**; selecting an entry starts the server again. The main process owns this state, so navigating away from Websites and back restores the current server status when the controls are reopened.

Up to four backend reads run concurrently per server, with a bounded queue for ordinary browser resource bursts. Owner destruction, disconnect or connection rebinding, application shutdown, and website identity replacement revoke the preview and close connections. Browser tabs remain open but cannot retrieve more content from the revoked origin. There is no preview session persisted across application restarts, content cache, or copied content directory.

## Transfer limits and server behavior

Directory imports skip dot-prefixed subdirectories (such as `.git`) at every depth unless **Include hidden directories** is checked. The checkbox starts unchecked for each import. This uses POSIX-style names only, not filesystem hidden attributes; non-empty dot-prefixed files remain included. The explicitly selected root directory is still imported. Both dropped and picker-selected directories skip zero-byte files, which this server cannot store, while importing their non-empty content. A selection with no non-empty files reports that nothing can be uploaded; explicitly selecting an empty file still reports an error.

The selected website's content card accepts dropped local files and directories. Files use `/filename`; directory contents use paths relative to the dropped directory under `/`, retaining nested folders and skipping hidden subdirectories by default. Preload resolves native-backed `File` objects into a private path envelope; renderer code neither receives local paths nor traverses directories. Main reads the entire bounded batch before submitting it, rejects symbolic links, special files, and duplicate destination paths, and detects each MIME type from known extensions, supported media signatures, or bounded text detection with a binary fallback. A drop uses the same aggregate file, byte, catalog, and backend identity checks as other imports.

Drops with no conflicting destination paths upload immediately. When paths already exist, main presents a native confirmation identifying the website and files to overwrite. **Overwrite** uploads the whole drop, replacing conflicting paths. **Skip existing** preserves those paths and uploads only new files; if every path already exists, it completes without a write. Main retains the bounded batch's bytes while the prompt is open and rechecks the current backend, website identity, and remaining upload destinations before an approved write. A new destination occupied during the prompt is rejected rather than overwritten. **Cancel** abandons the entire drop, including files whose paths are new, without writing or refreshing the website. Transient file bytes, including skipped files, are cleared after completion or cancellation.

Directory and multi-file drops show the current file number beside the spinner and a bar measuring confirmed uploads. Main validates the whole batch and catalog budget before writing, then uploads one file at a time under the shared mutation queue. Counts advance only after the server returns matching content; skipped and empty files are excluded from the total. A single directly dropped file keeps the indeterminate spinner. Progress contains only counts, is correlated to one invocation, and is delivered only to its initiating document; preload removes the listener when that invocation settles.

Individual imports and exports are bounded at 32 MiB, directory imports at 500 files, and text editing at 1 MiB. The pinned Sliver server includes hosted file bytes even in its website catalog response, while the SDK's inventory channel accepts at most 32 MiB. Before creating a website or uploading content, main computes the predicted encoded catalog size, including replacements and protobuf metadata, and rejects operations exceeding a 31 MiB aggregate budget. This leaves room for server-generated metadata without raising transport ceilings.

Website mutations sharing a GUI backend connection are serialized through their preflight and write steps. Native file and dropped-file overwrite dialogs do not hold that queue; selected content is checked again against its pre-dialog identity, digest, size, and MIME type. MIME-only changes do not resend stale size or digest metadata. This budget is a client preflight, not a server transaction. Another operator can change the catalog between checking and uploading, and a directory upload can partially succeed before a server error. Refresh after an error to inspect server state. Catalogs already exceeding the SDK's inventory limit cannot be listed through this GUI; reduce their content through the native console or another administrative client first. The GUI does not silently increase receive limits or retrieve content from a listener URL as a fallback.

Connection identity is checked again after asynchronous operations and native dialogs. Preview/export responses must match the requested website and content path; missing or mismatched bytes are rejected, and a supplied server SHA-256 must match the returned bytes. Export also rechecks content identity and digest after the save dialog. Preview bytes are cleared when dismissed, and main clears transient RPC/import/export buffers after use. Event summaries carry an inventory-change message, never hosted content.

## Verification

Source component/editor tests cover malicious content, safe editor configuration, language selection, malformed UTF-8, Unicode controls, missing bytes, truncation, and byte limits. Editing tests reject partial and inconsistent content.

`website-preview-server.test.ts` exercises a real loopback HTTP server: original bytes and MIME types, fresh reads after edits, resource paths, HEAD, cache headers, traversal and header rejection, read-only methods, worker blocking, connection revocation, resource request queuing, and transient-buffer clearing. Registry tests verify fresh authenticated reads, changed MIME types, missing resources, and rejection after website or connection changes. The Electron journey checks the browser URL handoff, content and resource requests, edits visible through the existing URL, opening and closing the preview controls without stopping the server, running website and URL visibility after selection and navigation changes, using the dropdown to switch to a website excluded by the sidebar filter without changing the editing selection, switching and stopping with HTTP revocation, restarting and reopening a preview, and preview revocation on disconnect.

The design keeps untrusted documents outside application views, following [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security/) and [context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation).
